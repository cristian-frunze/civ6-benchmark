# Rig setup

The game runs on a Windows laptop: an Asus Zenbook Duo with a Core Ultra 9 185H, 32 GB of RAM, Intel Arc graphics and Windows 11 Home. The agents run elsewhere and reach the laptop over Tailscale and SSH. A Linux server without a GPU can't run Civ 6 usefully: Proton builds don't expose FireTuner, and software rendering is too slow.

## One-time setup on the game PC

1. Install Civ 6 from Steam. civ6-mcp expects the **Gathering Storm** ruleset, and the CivBench scenario saves also need the New Frontier Pass civs. Check ownership with `lua/list-mods.lua`: files on disk don't mean the account owns the DLC.
2. Run `windows/apply-fast-settings.ps1`. It backs up the three options files, then sets:
   - borderless window at the primary screen's size (default 2880x1800) with the UI at 200%, no audio, no intro video
   - every graphics option at minimum, with shadows, bloom, lighting, clouds and AO off
   - quick movement and quick combat, no combat camera, no vignettes or historic-moment animations
   - start in strategic view, tutorial and expansion intro screens marked as seen
   - `EnableTuner 1`, `AutoEndTurn 0`
3. Run `windows/setup-civ6-mcp.ps1` (clones civ6-mcp and runs `uv sync`).
4. Run `windows/register-tasks.ps1`. It registers these interactive scheduled tasks:
   - `Civ6Launch`: starts the DX11 build
   - `Civ6Shot` and `Civ6Click`: screenshot and click
   - `Civ6Exec`: runs any PowerShell file in the desktop session, via `remote/zexec.sh`
   - `Civ6Mcp`: the long-lived civ6-mcp HTTP server
5. On the agent machine, run `remote/tunnel.sh` (an SSH tunnel to the server). Agents then use `http://127.0.0.1:18771/mcp`.
6. Optional, for watching: `windows/open-warroom.ps1` opens the war room page full screen on the second screen. It reads its URL from a local `warroom.json`.

## Things that were not obvious

- **SSH sessions can't open windows.** OpenSSH on Windows runs in session 0, so a GUI started from SSH never shows on the desktop. Launching, screenshots and clicks go through scheduled tasks with `LogonType Interactive`, which run in the signed-in user's desktop session. Register them with the identity from `WindowsIdentity.GetCurrent().Name`, not `$env:USERDOMAIN` (that is `WORKGROUP` over SSH).
- **FireTuner works from SSH.** The game listens on `127.0.0.1:4318`, and loopback TCP crosses sessions, so the MCP server can run in the SSH session. It takes about 2 minutes after launch to open.
- **The Lua state list alternates ID and name** (`['0', 'Main State', '1', 'DebugHotloadCache', '2', 'IntroScreen', ...]`). Send commands to the number before the name, not to the list index.
- **Output lines start with `O<NUL><state>: `.** Strip the prefix, NUL byte included.
- **The copyright screen ignores synthetic clicks.** Run `OnAccept()` in the `IntroScreen` state instead (`lua/accept-eula.lua`).
- **Front-end save names include the extension** (`0A_GROUND_CONTROL.Civ6Save`).
- **OneDrive moves Documents.** Civ 6 writes saves to `OneDrive\Documents\My Games`, while civ6-mcp looks in `%USERPROFILE%\Documents\My Games`. A directory junction from the second path to the first fixes it.
- **"One or more Mods has not been purchased"** means the save needs DLC the Steam account doesn't own, even when the files are installed. `Modding.GetInstalledMods()` reports `Allowance=false` for those.
- **FireTuner takes one client at a time.** While a client is connected, the game stops listening on 4318. So civ6-mcp runs as one long-lived HTTP server (`windows/civ_mcp_http.py`) that holds the only connection. Agents connect to that server, and nothing else talks to the tuner during a game. Over SSH stdio, every agent restart killed the server abruptly, and civ6-mcp warns that an abrupt tuner disconnect can crash the game.
- **The MCP SDK runs the server lifespan once per client session.** civ6-mcp opens its tuner connection in the lifespan, so the HTTP wrapper shares one lifespan across sessions. It also no-ops civ6-mcp's side web API on port 8000, whose shutdown took the main server down.
- **Use the DX11 build on the Zenbook Duo.** DX12 crashed with "Device Reset" (DXGI 0x887a0005) when the second screen turned on. Steam asks which build to launch the first time; tick "Always use this option".
- **Borderless, not fullscreen.** Exclusive fullscreen minimizes when you click the other screen. `FullScreen 2` is borderless at the desktop size, and `UIUpscale 1.0` is 200%.
- **Tailscale DNS may be off on the game PC.** If it is, the war room browser maps the share hostname to the server's tailnet IP with `--host-resolver-rules`, in its own profile, so the laptop's DNS settings stay as they are.
- **civ6-mcp is built for Gathering Storm.** On the base game, `get_game_overview` fails on `GetFavor()`, and about 60 Lua call sites use Rise and Fall or Gathering Storm functions. The HTTP wrapper rewrites them to `CB_` stand-ins (see the README). It adds only new names: the game's own UI checks names like `Game.GetEras` to detect expansions, so redefining those could change its behavior.
- **Never call engine getters blindly.** A probe that called every `Get*` method on game objects crashed the game; `pcall` doesn't catch a native crash. civ6-mcp's `restart_and_load` brought it back in about 2.5 minutes.
- **Base-game alliances unlock with Civil Service**, not Diplomatic Service (`GameInfo.DiplomaticActions`), and science victory takes 5 space projects (3 for Mars).
- **Pin civ6-mcp's run id per game.** It names its diary and logs `{kind}_{civ}_{seed}_{run id}` and draws a new run id at every server start, so a mid-game restart would hand the agent an empty diary. `run_game.py --prepare` sets `CIV_MCP_RUN_ID` to the game id.
- **Headless Claude Code drops thinking text** unless you pass `--thinking-display summarized`; the `showThinkingSummaries` setting only applies to interactive sessions.
- **Windows OpenSSH limits:** a command line holds about 32K characters, and stdin piped to PowerShell hangs past about 8 KB. `remote/zput.sh` sends files in 4 KB chunks, and the archive keeps its request small.
- **A save load can move a unit.** civ6-mcp closes the leader screen by clicking CONTINUE GAME near the bottom of the screen. When the screen closes between mouse down and mouse up, the click lands on the map and walks the selected unit toward it: game 1's first try lost turn 1 when its settler walked two tiles off the river. It depends on timing (the same load was clean an hour earlier), so `run_game.py --prepare` checks that every unit has full moves after loading a turn-start save, and loads it again if not. civ6-mcp's own mid-game recovery reloads have the same risk; the archive's per-turn saves and screenshots show it if it happens.
- **Turn the tutorial off (`TutorialLevel -1` in `UserOptions.txt`).** At level 0, Advisor popups ("Our explorers have spotted another friendly Tribal Village...") hold the end of turn, and civ6-mcp's popup handling doesn't know them, so `end_turn` waits until someone clicks OK (game 1's second try stalled 5 minutes on turn 3). The game reads the level once at launch. `windows/apply-fast-settings.ps1` sets it; check it in-game with `UserConfiguration.TutorialLevel()`.
- **civ6-mcp's OCR finds saves in the Autosaves list but missed a custom name in the regular list.** `run_game.py --start-save` copies a kept start into the autosave folder as `AutoSave_0001` and loads it from there.
- **civ6-mcp's `end_turn` can wait 10 minutes on a unit that needs orders.** Its blocker scan reads notifications, which in the base game miss units with moves left, and it trusts `UI.CanEndTurn()`, which can be true while the game still refuses the turn. It then sends the end turn and polls for about 10 minutes. Game 1 stalled on turn 10 and turn 13 this way. The HTTP wrapper now asks the game's own blocker first (`NotificationManager.GetFirstEndTurnBlocking`, which the base game's end-turn button uses) and returns the units with moves left in under a second.
- **A leader screen left open stalls the AI turns.** When civ6-mcp closes an AI greeting itself (`DiplomacyManager.CloseSession`, its "goodbye phase" auto-close), the leader screen can stay up in its overview mode, and the AI turns don't finish while it is up. Game 1 hung 10 minutes on turn 92, civ6-mcp reloaded the turn, and it stalled again until the screen was closed. The HTTP wrapper now closes a leader screen that has no open session after every diplomacy or trade reply and before `end_turn`. It fires `LuaEvents.NaturalWonderPopup_Shown`, which the screen answers with its own `Close()`, as civ6-mcp does after a war declaration.
- **civ6-mcp binds its records to the game only in `get_game_overview`.** After a server restart, a resumed agent played turns 101-105 from `end_turn` results alone, and the call log and diary waited in memory until something called the overview. The HTTP wrapper now binds on the first call of any tool, and `tools/timeline.py` gives a call with no turn the turn of the call before it.
- **Turn the screensaver off.** On the Zenbook, Asus's "OLED Care" screensaver took over the input desktop around midnight during game 2. Screenshots failed ("the handle is invalid"), and civ6-mcp's hang recovery relaunched the game but could not click through the menus to reload the turn. `windows/apply-fast-settings.ps1` turns it off, but Asus software turned it back on and it stopped game 2 again on turn 238. The `Civ6Awake` task (`windows/keep-awake.ps1`, registered by `register-tasks.ps1`) now runs in the desktop session the whole time: it keeps the display on, moves the mouse by 0 pixels every 50 s, and stops any screensaver that starts anyway.
- **Don't query the UI context while the AI civs move.** civ6-mcp polls only GameCore during the AI turns because InGame queries can stall them. Game 2 hung on turn 145 after an AI trade proposal paused the end of turn 144: the turn number then read 145 before the player's turn had started, the agent's moves failed with NO_MOVES, and its next end_turn hung until civ6-mcp reloaded the turn. The HTTP wrapper's end_turn checks (unit orders, leader screen) ran in the InGame context, so now they first ask GameCore whether the player's turn is active, wait for it if not, and skip themselves while a turn end is still in flight.
- **Claude Code aborts an MCP tool call after 300 s of silence.** An AI turn late in the game can take longer, so `run_game.py` sets `"timeout": 900000` (ms) on the civ6 server in the agent's `mcp.json`.
- **PowerShell doesn't expand `%USERPROFILE%`**, and single-quoted `$env:USERPROFILE` stays literal. Paths sent to the game PC go through `[Environment]::ExpandEnvironmentVariables`.
- **FireTuner is disabled in every multiplayer mode, hotseat included.** Multi-agent games need the file-based MCP Bridge UI mod from Johnor12/civ6-mcp, or single-player puppeteering (civ6-mcp `docs/agent-vs-agent.md`).
- **Future Tech repeats.** Once every tech is researched, the game asks for Future Tech again each turn, but civ6-mcp's `set_research` refused anything already researched, so game 2 could not end turn 238. `bench_compat.py` now lets `set_research` and `set_civic` pick a repeatable tech or civic again.
- **Started outside Steam, Civ 6 exits and Steam starts it again.** The FireTuner port of the first process can open and close again, and the second start once took about 5 minutes with no window. `new-start.ps1` waits up to 5 minutes for the port and the main menu, and `$NoRestart = 1` skips the relaunch when the game already sits at the main menu.
- **PowerShell variable names ignore case.** `$Lua` and `$lua` are the same variable, so a setting named like a script's own variable silently replaces it.
- **Online speed has a 250-turn limit** (GameSpeed_Turns: 35+30+20+20+30+25+60+30). The same seed gives the same AI leaders in the same slots as the Quick start: Trajan, Gorgo, Pedro II, Barbarossa, Teddy Roosevelt, Cleopatra and Philip II.
- **Hotseat games start from the main menu over FireTuner, then finish over the bridge.** `new-start.ps1` with `$LuaFile = 'new-hotseat.lua'` hosts the game (it waits in the staging room), the Civ6Mcp task runs the hotseat server when `mcp-env.json` has `"CIV_MCP_SERVER": "hotseat"`, and the coordinator tool `bench_launch_staged_game` starts it. The hotseat player names set in Lua don't stick (the turn-change screen says "Player 1"), which doesn't matter: seats are told apart by leader.
- **A hotseat game holds one machine slot and staggers once.** Each seat turn is a new `claude -p` run. Through `claude-acct`, each one waited for a second headless slot (`claude-slot`) and for the machine-wide 5-second launch stagger, about 6 minutes per seat turn on the busy dev server, against 20 seconds of Claude's own time. `run_hotseat.py` now takes one slot and one stagger turn for the whole game (only one seat plays at a time) and starts `claude` straight under the account's config dir. Seat turns in the smoke test then took 34-42 s.
- **The AI civs also wait on a diplomacy session they open mid-turn.** In game 4, civ6-mcp auto-dismissed Brazil's war declaration during the end of turn 58 and reported that the turn had not advanced, while the AI turn was in fact still running. America then opened a session (a delegation offer), and the AI civs waited about 20 minutes for an answer: the wrapper's end_turn guard only waited for the player's turn, so nothing told the agent about the session, and it finally reloaded the turn. While the AI civs move, end_turn now also checks for an open session once on entry and once at 45 s (one InGame query each, as civ6-mcp's own polling does) and tells the agent to answer it.
- **A restarted MCP server costs the agent one tool call.** Claude Code reconnects to a restarted HTTP MCP server by itself: the call in flight fails ("connection closed before the tool call was answered"), calls while the server is down fail ("not connected"), and the next call after it is back works. Restart it right after an `end_turn` returns, never during one, since a fresh server forgets a turn end in flight.
- **New starts:** `remote/make-start.sh <name> [speed] [difficulty] [seed]` runs `new-start.ps1`, clicks BEGIN GAME, waits for the turn-1 autosave and keeps it with `keep-start.ps1`. The Prince and Deity starts differ only in the difficulty setting (same seed and settings); the Deity AIs start with extra units.
- **A hotseat AI turn can hang for good.** In game h1, after the last Opus seat ended turn 53, the AI civs' turn never finished: the game sat on the turn-change screen's "please wait" state for 49 minutes, with no Lua error and no pending diplomacy. Reloading the save `end_turn` made at the start of that seat's turn (`load_hotseat_save`) fixed it: the seat replayed its turn and the AI civs then finished in seconds. `tools/hotseat_doctor.py` now runs beside a hotseat game and does this by itself after 20 idle minutes, at most twice per turn, and logs each reload in the run's `interventions.jsonl`. It hung five times in h1's 157 turns (turns 53, 93, 111, 120, 141), always right after the last agent seat.
- **A diplomacy pause can make the agent end a turn it never played.** An AI civ often opens a proposal during the AI turn; civ6-mcp's `end_turn` stops with "Use respond_to_diplomacy to handle it, then end_turn again" (and the guard in `windows/civ_mcp_http.py` says the same). Once answered, the AI turn finishes and the agent's next turn has already begun, so "end_turn again" ends that new turn. `tools/turn_trap.py` counts it from the tool log: 0 to 11 turns per Opus game, 8 in the Sonnet game, 0 in game 8 on the fix. The cause is in civ6-mcp: with the old end-turn request still in flight, `end_turn` first checks end-turn blockers, which by then belong to the new turn, and reports them as if the old turn were still open. From game 8 on, `windows/civ_mcp_http.py` skips that first check while a request is in flight (civ6-mcp then reports the turn change, headed "Turn N ended while you answered the AI civ ... Your turn N+1 is now open"), and after the agent answers a session the AI civs were waiting on, it refuses the first `end_turn` of the new turn once unless the agent has given an order or read the overview since. Game 7 still ran on the old harness, to repeat game 3 exactly.
- **Menu loads failed because the game ignored civ6-mcp's clicks.** civ6-mcp loads saves by OCR: it reads the game window's own pixels, finds "Single Player", moves the cursor there and clicks, then looks for "Load Game". Two things made every click miss while OCR still read the menu fine. (1) A window over the game takes the click: one night a browser on the game's screen opened its onboarding page, and civ6-mcp's `SetForegroundWindow` is refused for a background process, silently. (2) The game's menu only takes a click on a button the mouse has moved over. Once a click was lost, the cursor stayed on "Single Player", so every later click, after each relaunch too, came with no movement and was ignored. Game 7 lost 67 minutes to it at turn 102, and game 8 failed 6 start loads in two starts (its runner also died once when a `get_units` check at the main menu ran past its 120 s timeout). `windows/civ_mcp_http.py` now raises the game window in the z-order when it is not in front, starts every click 40 px away from its target, and clicks "Single Player" again if "Load Game" does not appear. `run_game.py` treats a timed-out call as a failed check and skips the checks after a load that reports FAILED. Tested on the PC: with the cursor parked on "Single Player", `restart_and_load` failed before the fix and loaded on the first try after it.
- **civ6-mcp can name a Science win a Score victory.** When a space race ends, the game does not count the last project yet, so civ6-mcp's science test sees 4 of 5 and falls back to Score (game 6; in game 5 a check 39 s later said Technology). `bench_compat.py` names a win before the turn limit by a civ one project short a Science victory.
- **A hotseat win can come mid-turn and freeze the game.** In h1, Rome finished its last space project on turn 157 by activating a Great Engineer. The game then refused every order, `end_turn` kept failing on units with moves left, and through the bridge no victory screen showed. `Game.GetWinningTeam()` did report the winner, so `run_hotseat.py` now asks for it (`bench_stats`) after every seat turn, not only at the start of a round.
- **Trades hung the next end turn, because civ6-mcp hid the diplomacy screen instead of closing it.** The screen locks the engine's event queue when it opens (`m_eventID = UI.ReferenceCurrentEvent()`, "lock engine", in the base game's `DiplomacyActionView.lua`) and releases it only in its own `Close()`. A session the AI started closes the screen when it ends. A session the player started (every `propose_trade`) only takes it back to the overview, and the game then closes it when the player's turn ends, but only if it is visible. civ6-mcp's `propose_trade` hid it (`SetHide(true)`), so nothing closed it and the AI turns stalled behind the lock until civ6-mcp's 10-minute hang recovery reloaded the turn. Across games 1 to 8, 14 of the 23 end turns after a `propose_trade` hung, refused trades included, against 3 of 1,600 after turns with no diplomacy, and every trade turn of game 8 (turns 207 to 213) hung. From game 10 on, `windows/civ_mcp_http.py` leaves the screen up after a trade and closes it with `LuaEvents.NaturalWonderPopup_Shown` (the leader-screen fix above), retrying up to 3 times, after every trade or diplomacy tool and before `end_turn`. Only two things in the base game UI take that lock: this screen and the popup manager (`PopupManager.lua`), whose popups civ6-mcp already dismisses before each end turn.
- **A first-contact greeting can cancel the end-turn request.** In game 8, Spain greeted the player during the end of turn 13. civ6-mcp reported "Turn paused" and, after the answer, waited for its request to finish, but the turn never ended, and each hang reload brought the greeting back: 11 hangs and 2.4 hours, until the agent loaded turn 12 and moved its units elsewhere. In game 7, a new end turn sent after answering the same greeting ended the turn in 25 s. From game 10 on, when civ6-mcp still waits on its request but the turn number is unchanged and the player's turn is active (checked twice, 3 s apart), the wrapper's `end_turn` drops the stale request and sends a new one. While the AI civs move, the player's turn is inactive, so a request still in flight is never sent twice.
- **civ6-mcp's hang recovery undoes the turn without saying so.** It reloads the save it made when the turn started (`0_MCP_NNNN`, written right after the turn change) and ends the turn again, then returns only that second result. The agent's orders, production and research choices and trades for that turn are gone. In game 8 the agent took the reloads for crashes and stopped trading. From game 10 on, `end_turn` starts its result with a note naming the reload and what it undid.
- **A melee attack from 2 or more tiles away always came back as "STOPPED_SHORT", even when it worked.** It is a move-and-attack: civ6-mcp sends the order and reads the unit's tile in the same Lua call, before the order has run, so the unit is still on its starting tile and the agent reads "could not reach target ... Try again next turn from closer position". That happened 12 to 26 times a game. In games 3, 7 and 8, the next unit listing (2 to 3 seconds later) showed the unit had moved every time, and most of the time it had attacked: the target had lost HP, or died and the unit stood on its tile. Agents then tried to move the same unit again and got `NO_MOVES`. From game 10 on, `windows/civ_mcp_http.py` reads the unit and the target tile again every 0.5 s, for up to 6 s, until the outcome shows, and reports it: the attack with both HP changes, the unit's death, a move that ended next to the target without attacking, or a real stop short with the unit's new tile.
- **A ranged unit's refused shot turned into a move.** When the game refused a ranged attack on an adjacent target (`UnitManager.CanStartOperation` for `RANGE_ATTACK` false), civ6-mcp fell back to a melee move-and-attack. Ranged units cannot melee, so the unit only moved, usually out of the city it garrisoned: 14 times in games 1 to 9, 11 of them from a city tile, against 162 adjacent shots that worked. Why the game refused is unknown: the same units fired on the agent's next call. civ6-mcp's combat estimate also treated every adjacent shot as melee, with melee strength, river and flanking modifiers and damage to the attacker. From game 10 on, a ranged unit always takes the ranged path, a refused adjacent shot is tried again a second later, and if the game still refuses, the unit stays put and the agent gets `RANGED_REFUSED`. The estimate counts every attack by a ranged unit as ranged.
- **Promotions broke the game's rule.** civ6-mcp applies a promotion with GameCore's `SetPromotion` (its authors found the game's own `PROMOTE` command failed silently), then healed the unit to full and left its moves. In the game, a promotion heals `EXPERIENCE_PROMOTE_HEALED` HP (50 in the base game's `GlobalParameters.xml`) and ends the unit's turn. Agents noticed and used it ("Promotion did not consume War-Cart's moves and healed it fully - promote before attacking when possible", game 9, turn 27). From game 10 on, a promotion heals the game's amount and ends the unit's turn, and the result says so.
- **Auto-explore and multi-turn moves stopped after `skip_remaining_units`.** `unit_action`'s `automate` sends the game's own `UNITOPERATION_AUTOMATE_EXPLORE`, as the game's unit panel does. The scout explored that turn, but from the next turn on it sat on its tile with full moves and needed orders again (game 8, turns 19-20 at (38,38) and 24-25 at (37,34); game 9: "Scout automate doesn't persist; manual moves"). Agents said the same of long moves ("Move orders don't persist across turns; reissue each turn"). The cause is `skip_remaining_units`, which agents call before nearly every `end_turn`. It fortifies and then ends the moves of every unit with moves left. The game moves auto-exploring units when the turn ends, so with their moves gone they stayed put: on 23 of 24 turns with a skip, against 2 of 9 without. A long move is hit the same way: civ6-mcp reports "STOPPED_MID_PATH (moves exhausted)" whenever the unit is not on its target at the instant it reads the tile, often while the unit is still walking. 106 of 152 multi-turn moves followed by a skip had stopped by the next turn, against 0 of 3 with no skip. From game 10 on, `skip_remaining_units` waits until the game has finished moving units (`UI.IsGameCoreBusy`). It then skips only the units the game itself counts as waiting for orders (`unit:IsReadyToSelect()`, no queued destination), and says how many it left alone. The harness also sends auto-explore again at the start of each of the agent's turns, with a line in the `end_turn` result, until the agent gives that unit another order or the unit stops moving.
- **Hidden resources leaked.** A strategic resource stays hidden until its tech (`Resources.PrereqTech`: Niter needs Military Engineering, Iron needs Bronze Working). civ6-mcp's map tools hide it until then, but `get_cities` ("Needs builder: NITER@x,y", in every briefing), `get_builder_tasks` and the wonder advisor named it: game 9 had a Niter mine listed as URGENT on turn 29. From game 10 on, those three read resources through the same check.
- **A city attack on a target out of sight crashed.** civ6-mcp's NO_LOS message sits outside its f-string, so the Lua concatenates a table (`{target_x}`) and fails with "operator .. is not supported for table .. string" (game 7, turn 113, where the agent blamed stacked units). Fixed from game 10 on.
- **Units the agent used up were reported as killed.** civ6-mcp's turn report calls every own unit missing after the turn "killed": settlers that founded cities, builders on their last charge, upgraded units (new id), disbanded ones. Those orders run asynchronously, so the unit is often still in the snapshot taken when `end_turn` starts: 22 to 35 false alarms a game in games 6 to 8. From game 10 on, the harness remembers the agent's own orders that can use a unit up and reports such a unit as used, not killed. A builder that had charges to spare is still reported as killed.
- **`get_gp_advisor` never worked.** It read the Great Person class from `Units.GreatPersonClass`, a column the game does not have, so all 7 calls in games 3, 6 and 7 failed. From game 10 on it looks the class up in `GreatPersonClasses`, which maps each class to its unit type.
- **The promotion blocker did not say which unit.** `end_turn` answered "Unit available for promotion -> Use: get_unit_promotions(unit_id=...)" 262 times in games 1 to 9 without naming one. From game 10 on, the line lists the units, found by the XP formula civ6-mcp's own blocker check uses.
- **Production orders the game held were reported as failed.** `set_city_production` sends the order and reads the city's queue straight back. While an exclusive popup is open (a natural wonder found, a wonder built, a tech completed) or an AI diplomacy session waits for an answer, the game holds orders, so the read-back found nothing and the agent got "SILENT_FAILURE ... Retry the same call": 16 times in games 1 to 8. The orders were not lost. In game 2, turn 224, the Moon Landing reported as failed was in the queue once the agent answered Germany's deal. In game 8, turn 179, the same orders worked right after `dismiss_popup`. From game 10 on, the harness names the session that holds the order ("ORDER_HELD ... answer it, the order then goes through by itself"). With no session open, it closes the popups, waits up to 3 s for the order to land and reports it, and sends it once more only if it still has not landed. The order replaces the queue, so a second copy cannot pile up.
- **Diplomacy pauses did not give the player id.** `end_turn` said "AI diplomatic proposal from Spain (Philip II)", and `respond_to_diplomacy` needs Spain's player id, which the pause did not give. Agents guessed (Spain's greeting answered as player 1 in games 3, 7 and 8, Brazil's in game 9) or answered after the session had closed, and got a bare `NO_SESSION`: 24 times in games 1 to 9. From game 10 on, the pause and the "diplomacy encounter pending" blocker give the id ("Spain (Philip II, player 7)"), and `NO_SESSION` lists the sessions that are open, or says none is.
- **The popup scan spent 20 s on a popup that never closes.** When an exclusive popup is up, civ6-mcp's `dismiss_popup` (also run before every end turn) calls `Close()` in every Lua state named like a popup until it hides, up to 20 times each. `InvitePopup` (multiplayer invites) never hides, so a third of the scans in games 8 and 9 (57 of 170) took about 27 s instead of 5 s, and the agent read "InvitePopup" 20 times in the list of closed popups. From game 10 on, the scan skips it.
- **Obsolete policies were offered, slotted, and dropped again every turn.** A policy goes obsolete once the policy that replaces it is unlocked (`ObsoletePolicies` in the base game's `Policies.xml`: Conscription when Levee en Masse is unlocked, Liberalism with New Deal, Urban Planning with Colonial Offices). The game's own government screen lists a policy only if `IsPolicyUnlocked` and not `IsPolicyObsolete`. civ6-mcp's `get_policies` skips the second check, and `set_policies` accepted the card. The game then took it out of its slot, and the next turn opened with an empty-slot blocker. Game 3 slotted Conscription again on 28 turns and Liberalism on 9. Game 4 slotted Conscription on 24 and Urban Planning on 9, and games 7 and 8 hit the same loop. Meanwhile the agents believed the policy was in effect. From game 10 on, `get_policies` leaves obsolete policies out, and `set_policies` refuses one and names the policy that replaced it.
- **A move did not say the unit had used up its moves.** A move that reached its tile reported where the unit stood but not that it had no moves left, so agents sent the next order at once: 20 to 42 `improve` orders a game (games 1 to 8) were refused with "no moves remaining" right after the builder's own move, and a Great Scientist moved onto its Campus was refused with no reason while the error listed that tile as valid (game 9, turn 67; it activated there the next turn). From game 10 the move result adds "arrived with no moves left", and a refused activation says when the unit has no moves.
- **A turn that ended was reported as not ended.** When a civ at war with the player opens a diplomacy session during the AI turns, civ6-mcp closes it and waits for the turn to change, but keeps the turn number it read before the session. The report then says "Turn 144 -> 144" (game 9, turn 144, right after the pause): 37 times in games 1 to 9, 27 of them in game 4, which was at war most of the game. The agents played on correctly each time, but the same stale number named the per-turn autosave. The start of the new turn was saved over the start of the old one, so `0_MCP_0144` held turn 145, and there was no `0_MCP_0145`, the save that a hang on turn 145 reloads. civ6-mcp's per-turn advisor budget did not reset either. From game 10 on, the autosave is named for the turn the game is on, and the report reads the turn after the end turn.
- **One turn report in six lost its events.** `end_turn` builds its report by comparing two snapshots of the empire, taken before and after the turn. The snapshot read the units in the game's GameCore context, but `get_units` reads them in the InGame context. civ6-mcp's units query checks line of sight with `UnitManager.CanStartOperation` whenever a ranged unit has an enemy in range but not adjacent, and GameCore has no such function. Then the whole read failed ("function expected instead of nil"), and the report lost the events from the comparison: units hurt or killed, buildings finished, cities grown. It happened 309 times in games 1 to 10 (to game 10's turn 60), about one turn in six, often on turns with fighting. The agent's own `get_units` never failed in about 1,000 calls. The snapshot now reads the units in the InGame context too. The fix came after game 10 started, so it loads from game 11.
