# Rig setup

The game runs on a Windows laptop: an Asus Zenbook Duo with a Core Ultra 9 185H, 32 GB of RAM, Intel Arc graphics and Windows 11 Home. The agents run elsewhere and reach the laptop over Tailscale and SSH. A Linux server without a GPU can't run Civ 6 usefully: Proton builds don't expose FireTuner, and software rendering is too slow.

## One-time setup on the game PC

1. Install Civ 6 from Steam. civ6-mcp expects the **Gathering Storm** ruleset, and the CivBench scenario saves also need the New Frontier Pass civs. Check ownership with `lua/list-mods.lua`: files on disk don't mean the account owns the DLC.
2. Run `windows/apply-fast-settings.ps1`. It backs up the three options files, then sets:
   - borderless window at the primary screen's size (default 2880x1800) with the UI at 200%, no audio, no intro video
   - every graphics option at minimum, with shadows, bloom, lighting, clouds and AO off
   - quick movement and quick combat, no combat camera, no vignettes or historic-moment animations
   - start in strategic view, tutorial and expansion intro screens marked as seen
   - `EnableTuner 1`, `AutoEndTurn 0`
3. Run `windows/setup-civ6-mcp.ps1` (clones civ6-mcp and runs `uv sync`).
4. Run `windows/register-tasks.ps1`. It registers these interactive scheduled tasks:
   - `Civ6Launch`: starts the DX11 build
   - `Civ6Shot` and `Civ6Click`: screenshot and click
   - `Civ6Exec`: runs any PowerShell file in the desktop session, via `remote/zexec.sh`
   - `Civ6Mcp`: the long-lived civ6-mcp HTTP server
5. On the agent machine, run `remote/tunnel.sh` (an SSH tunnel to the server). Agents then use `http://127.0.0.1:18771/mcp`.
6. Optional, for watching: `windows/open-warroom.ps1` opens the war room page full screen on the second screen. It reads its URL from a local `warroom.json`.

## Things that were not obvious

- **SSH sessions can't open windows.** OpenSSH on Windows runs in session 0, so a GUI started from SSH never shows on the desktop. Launching, screenshots and clicks go through scheduled tasks with `LogonType Interactive`, which run in the signed-in user's desktop session. Register them with the identity from `WindowsIdentity.GetCurrent().Name`, not `$env:USERDOMAIN` (that is `WORKGROUP` over SSH).
- **FireTuner works from SSH.** The game listens on `127.0.0.1:4318`, and loopback TCP crosses sessions, so the MCP server can run in the SSH session. It takes about 2 minutes after launch to open.
- **The Lua state list alternates ID and name** (`['0', 'Main State', '1', 'DebugHotloadCache', '2', 'IntroScreen', ...]`). Send commands to the number before the name, not to the list index.
- **Output lines start with `O<NUL><state>: `.** Strip the prefix, NUL byte included.
- **The copyright screen ignores synthetic clicks.** Run `OnAccept()` in the `IntroScreen` state instead (`lua/accept-eula.lua`).
- **Front-end save names include the extension** (`0A_GROUND_CONTROL.Civ6Save`).
- **OneDrive moves Documents.** Civ 6 writes saves to `OneDrive\Documents\My Games`, while civ6-mcp looks in `%USERPROFILE%\Documents\My Games`. A directory junction from the second path to the first fixes it.
- **"One or more Mods has not been purchased"** means the save needs DLC the Steam account doesn't own, even when the files are installed. `Modding.GetInstalledMods()` reports `Allowance=false` for those.
- **FireTuner takes one client at a time.** While a client is connected, the game stops listening on 4318. So civ6-mcp runs as one long-lived HTTP server (`windows/civ_mcp_http.py`) that holds the only connection. Agents connect to that server, and nothing else talks to the tuner during a game. Over SSH stdio, every agent restart killed the server abruptly, and civ6-mcp warns that an abrupt tuner disconnect can crash the game.
- **The MCP SDK runs the server lifespan once per client session.** civ6-mcp opens its tuner connection in the lifespan, so the HTTP wrapper shares one lifespan across sessions. It also no-ops civ6-mcp's side web API on port 8000, whose shutdown took the main server down.
- **Use the DX11 build on the Zenbook Duo.** DX12 crashed with "Device Reset" (DXGI 0x887a0005) when the second screen turned on. Steam asks which build to launch the first time; tick "Always use this option".
- **Borderless, not fullscreen.** Exclusive fullscreen minimizes when you click the other screen. `FullScreen 2` is borderless at the desktop size, and `UIUpscale 1.0` is 200%.
- **Tailscale DNS may be off on the game PC.** If it is, the war room browser maps the share hostname to the server's tailnet IP with `--host-resolver-rules`, in its own profile, so the laptop's DNS settings stay as they are.
- **civ6-mcp is built for Gathering Storm.** On the base game, `get_game_overview` fails on `GetFavor()`, and about 60 Lua call sites use Rise and Fall or Gathering Storm functions. The HTTP wrapper rewrites them to `CB_` stand-ins (see the README). It adds only new names: the game's own UI checks names like `Game.GetEras` to detect expansions, so redefining those could change its behavior.
- **Never call engine getters blindly.** A probe that called every `Get*` method on game objects crashed the game; `pcall` doesn't catch a native crash. civ6-mcp's `restart_and_load` brought it back in about 2.5 minutes.
- **Base-game alliances unlock with Civil Service**, not Diplomatic Service (`GameInfo.DiplomaticActions`), and science victory takes 5 space projects (3 for Mars).
- **Pin civ6-mcp's run id per game.** It names its diary and logs `{kind}_{civ}_{seed}_{run id}` and draws a new run id at every server start, so a mid-game restart would hand the agent an empty diary. `run_game.py --prepare` sets `CIV_MCP_RUN_ID` to the game id.
- **Headless Claude Code drops thinking text** unless you pass `--thinking-display summarized`; the `showThinkingSummaries` setting only applies to interactive sessions.
- **Windows OpenSSH limits:** a command line holds about 32K characters, and stdin piped to PowerShell hangs past about 8 KB. `remote/zput.sh` sends files in 4 KB chunks, and the archive keeps its request small.
- **A save load can move a unit.** civ6-mcp closes the leader screen by clicking CONTINUE GAME near the bottom of the screen. When the screen closes between mouse down and mouse up, the click lands on the map and walks the selected unit toward it: game 1's first try lost turn 1 when its settler walked two tiles off the river. It depends on timing (the same load was clean an hour earlier), so `run_game.py --prepare` checks that every unit has full moves after loading a turn-start save, and loads it again if not. civ6-mcp's own mid-game recovery reloads have the same risk; the archive's per-turn saves and screenshots show it if it happens.
- **Turn the tutorial off (`TutorialLevel -1` in `UserOptions.txt`).** At level 0, Advisor popups ("Our explorers have spotted another friendly Tribal Village...") hold the end of turn, and civ6-mcp's popup handling doesn't know them, so `end_turn` waits until someone clicks OK (game 1's second try stalled 5 minutes on turn 3). The game reads the level once at launch. `windows/apply-fast-settings.ps1` sets it; check it in-game with `UserConfiguration.TutorialLevel()`.
- **civ6-mcp's OCR finds saves in the Autosaves list but missed a custom name in the regular list.** `run_game.py --start-save` copies a kept start into the autosave folder as `AutoSave_0001` and loads it from there.
- **civ6-mcp's `end_turn` can wait 10 minutes on a unit that needs orders.** Its blocker scan reads notifications, which in the base game miss units with moves left, and it trusts `UI.CanEndTurn()`, which can be true while the game still refuses the turn. It then sends the end turn and polls for about 10 minutes. Game 1 stalled on turn 10 and turn 13 this way. The HTTP wrapper now asks the game's own blocker first (`NotificationManager.GetFirstEndTurnBlocking`, which the base game's end-turn button uses) and returns the units with moves left in under a second.
- **A leader screen left open stalls the AI turns.** When civ6-mcp closes an AI greeting itself (`DiplomacyManager.CloseSession`, its "goodbye phase" auto-close), the leader screen can stay up in its overview mode, and the AI turns don't finish while it is up. Game 1 hung 10 minutes on turn 92, civ6-mcp reloaded the turn, and it stalled again until the screen was closed. The HTTP wrapper now closes a leader screen that has no open session after every diplomacy or trade reply and before `end_turn`. It fires `LuaEvents.NaturalWonderPopup_Shown`, which the screen answers with its own `Close()`, as civ6-mcp does after a war declaration.
- **civ6-mcp binds its records to the game only in `get_game_overview`.** After a server restart, a resumed agent played turns 101-105 from `end_turn` results alone, and the call log and diary waited in memory until something called the overview. The HTTP wrapper now binds on the first call of any tool, and `tools/timeline.py` gives a call with no turn the turn of the call before it.
- **Turn the screensaver off.** On the Zenbook, Asus's "OLED Care" screensaver took over the input desktop around midnight during game 2. Screenshots failed ("the handle is invalid"), and civ6-mcp's hang recovery relaunched the game but could not click through the menus to reload the turn. `windows/apply-fast-settings.ps1` turns it off, but Asus software turned it back on and it stopped game 2 again on turn 238. The `Civ6Awake` task (`windows/keep-awake.ps1`, registered by `register-tasks.ps1`) now runs in the desktop session the whole time: it keeps the display on, moves the mouse by 0 pixels every 50 s, and stops any screensaver that starts anyway.
- **Don't query the UI context while the AI civs move.** civ6-mcp polls only GameCore during the AI turns because InGame queries can stall them. Game 2 hung on turn 145 after an AI trade proposal paused the end of turn 144: the turn number then read 145 before the player's turn had started, the agent's moves failed with NO_MOVES, and its next end_turn hung until civ6-mcp reloaded the turn. The HTTP wrapper's end_turn checks (unit orders, leader screen) ran in the InGame context, so now they first ask GameCore whether the player's turn is active, wait for it if not, and skip themselves while a turn end is still in flight.
- **Claude Code aborts an MCP tool call after 300 s of silence.** An AI turn late in the game can take longer, so `run_game.py` sets `"timeout": 900000` (ms) on the civ6 server in the agent's `mcp.json`.
- **PowerShell doesn't expand `%USERPROFILE%`**, and single-quoted `$env:USERPROFILE` stays literal. Paths sent to the game PC go through `[Environment]::ExpandEnvironmentVariables`.
- **FireTuner is disabled in every multiplayer mode, hotseat included.** Multi-agent games need the file-based MCP Bridge UI mod from Johnor12/civ6-mcp, or single-player puppeteering (civ6-mcp `docs/agent-vs-agent.md`).
- **Future Tech repeats.** Once every tech is researched, the game asks for Future Tech again each turn, but civ6-mcp's `set_research` refused anything already researched, so game 2 could not end turn 238. `bench_compat.py` now lets `set_research` and `set_civic` pick a repeatable tech or civic again.
- **Started outside Steam, Civ 6 exits and Steam starts it again.** The FireTuner port of the first process can open and close again, and the second start once took about 5 minutes with no window. `new-start.ps1` waits up to 5 minutes for the port and the main menu, and `$NoRestart = 1` skips the relaunch when the game already sits at the main menu.
- **PowerShell variable names ignore case.** `$Lua` and `$lua` are the same variable, so a setting named like a script's own variable silently replaces it.
- **Online speed has a 250-turn limit** (GameSpeed_Turns: 35+30+20+20+30+25+60+30). The same seed gives the same AI leaders in the same slots as the Quick start: Trajan, Gorgo, Pedro II, Barbarossa, Teddy Roosevelt, Cleopatra and Philip II.
- **Hotseat games start from the main menu over FireTuner, then finish over the bridge.** `new-start.ps1` with `$LuaFile = 'new-hotseat.lua'` hosts the game (it waits in the staging room), the Civ6Mcp task runs the hotseat server when `mcp-env.json` has `"CIV_MCP_SERVER": "hotseat"`, and the coordinator tool `bench_launch_staged_game` starts it. The hotseat player names set in Lua don't stick (the turn-change screen says "Player 1"), which doesn't matter: seats are told apart by leader.
- **A hotseat game holds one machine slot and staggers once.** Each seat turn is a new `claude -p` run. Through `claude-acct`, each one waited for a second headless slot (`claude-slot`) and for the machine-wide 5-second launch stagger, about 6 minutes per seat turn on the busy dev server, against 20 seconds of Claude's own time. `run_hotseat.py` now takes one slot and one stagger turn for the whole game (only one seat plays at a time) and starts `claude` straight under the account's config dir. Seat turns in the smoke test then took 34-42 s.
- **The AI civs also wait on a diplomacy session they open mid-turn.** In game 4, civ6-mcp auto-dismissed Brazil's war declaration during the end of turn 58 and reported that the turn had not advanced, while the AI turn was in fact still running. America then opened a session (a delegation offer), and the AI civs waited about 20 minutes for an answer: the wrapper's end_turn guard only waited for the player's turn, so nothing told the agent about the session, and it finally reloaded the turn. While the AI civs move, end_turn now also checks for an open session once on entry and once at 45 s (one InGame query each, as civ6-mcp's own polling does) and tells the agent to answer it.
- **A restarted MCP server costs the agent one tool call.** Claude Code reconnects to a restarted HTTP MCP server by itself: the call in flight fails ("connection closed before the tool call was answered"), calls while the server is down fail ("not connected"), and the next call after it is back works. Restart it right after an `end_turn` returns, never during one, since a fresh server forgets a turn end in flight.
- **New starts:** `remote/make-start.sh <name> [speed] [difficulty] [seed]` runs `new-start.ps1`, clicks BEGIN GAME, waits for the turn-1 autosave and keeps it with `keep-start.ps1`. The Prince and Deity starts differ only in the difficulty setting (same seed and settings); the Deity AIs start with extra units.
- **A hotseat AI turn can hang for good.** In game h1, after the last Opus seat ended turn 53, the AI civs' turn never finished: the game sat on the turn-change screen's "please wait" state for 49 minutes, with no Lua error and no pending diplomacy. Reloading the save `end_turn` made at the start of that seat's turn (`load_hotseat_save`) fixed it: the seat replayed its turn and the AI civs then finished in seconds. `tools/hotseat_doctor.py` now runs beside a hotseat game and does this by itself after 20 idle minutes, at most twice per turn, and logs each reload in the run's `interventions.jsonl`. It hung five times in h1's 157 turns (turns 53, 93, 111, 120, 141), always right after the last agent seat.
- **A diplomacy pause can make the agent end a turn it never played.** An AI civ often opens a proposal during the AI turn; civ6-mcp's `end_turn` stops with "Use respond_to_diplomacy to handle it, then end_turn again" (and the guard in `windows/civ_mcp_http.py` says the same). Once answered, the AI turn finishes and the agent's next turn has already begun, so "end_turn again" ends that new turn. `tools/turn_trap.py` counts it from the tool log: 0 to 14 turns per Opus game, 9 in the Sonnet game. It stays as it is through game 9 so those games match games 3 and 6; the fix is to tell the agent to check whether its next turn has started.
- **civ6-mcp can name a Science win a Score victory.** When a space race ends, the game does not count the last project yet, so civ6-mcp's science test sees 4 of 5 and falls back to Score (game 6; in game 5 a check 39 s later said Technology). `bench_compat.py` names a win before the turn limit by a civ one project short a Science victory.
- **A hotseat win can come mid-turn and freeze the game.** In h1, Rome finished its last space project on turn 157 by activating a Great Engineer. The game then refused every order, `end_turn` kept failing on units with moves left, and through the bridge no victory screen showed. `Game.GetWinningTeam()` did report the winner, so `run_hotseat.py` now asks for it (`bench_stats`) after every seat turn, not only at the start of a round.
